## 1:39–3:08 — LIVE PRODUCT DEMO (walkthrough.mp4, ~1:29)

This is the live screen recording. Narrate it like you're driving the demo live — say what you're doing as you do it, not just what's happening.

### Beat 1 — Set the scene (~0:00–0:20)
**Screen:** CapacityOS sandbox, idle, provenance badges visible
**VO:**
> "This is CapacityOS. The demand curve you're seeing is a real grid demand pattern from this region's actual historical data, scaled to this zone. Everything around it — the homes, the batteries, the EV fleets — is a modeled population built to behave like a real community would. I'm picking a hot summer afternoon to stress-test, and this capacity line is an editable assumption — not a hard-coded number."

### Beat 2 — Design the program (~0:20–0:36)
**Screen:** program editor open, incentive slider set to $130
**VO:**
> "First, I'm designing the actual program — how many devices are enrolled, what incentive we're offering, how much reserve each battery keeps back, how flexible EV charging and building comfort can be. These sliders are the real levers a utility or aggregator would pull."

### Beat 3 — Add the growth (~0:36–0:50)
**Screen:** dragging in a data centre and a housing development
**VO:**
> "Now watch — I'm dropping in a new AI data centre, and a housing development, right into this zone. [pause] And there it is — we just blew past the modeled capacity limit. So now the real question: can this program actually close that gap?"

### Beat 4 — Let the owners respond (~0:50–1:10)
**Screen:** live owner-agent negotiation running
**VO:**
> "CapacityOS sends the exact same flexibility request out to every device owner — nobody's forced, nobody gets a quota. Each one independently decides: offer flexibility, at what price, or decline. That's the participation side of a virtual power plant, modeled honestly, not scripted to look good."

### Beat 5 — Read the real result (~1:10–1:20)
**Screen:** Result tab — "Partly holds," 6.2 MW absorbed of 7.3 MW needed
**VO:**
> "And here's the result: partly holds. The program absorbed 6.2 megawatts — most of it — but about a megawatt is still uncovered. This is the honest answer, not a rigged demo. The program helped. It didn't fully close the gap. So — what would it actually take?"

### Beat 6 — Show the guardrails (~1:20–1:35)
**Screen:** Log tab — owner offers, a real rejection, a real revision
**VO:**
> "Every offer gets checked against real physics before it counts — battery limits, EV deadlines, building comfort. Only valid offers make it to the optimizer, which picks the cheapest combination that closes the gap. In plain terms: the AI proposes, physics constrains it, and math makes the final call."

### Beat 7 — Fix it (~1:35–1:55)
**Screen:** Fix It tab — tested pathways, measured improvement
**VO:**
> "This is the differentiator. CapacityOS doesn't just report the failure — it goes and tests fixes. More participation, a different incentive, more battery capacity, even a physical upgrade as a fallback — twenty to thirty real reruns of the simulation, not guesses. And each pathway here is verified: this is the actual reduction in the remaining gap, not an estimate."

### Beat 8 — Prove it holds up (~1:55–2:05)
**Screen:** Seasons tab — same program across different historical conditions
**VO:**
> "But one good result isn't proof. So I run the same program across different seasons and conditions from our historical data — because a planner needs to know where this breaks, not just where it works."

### Beat 9 — The paper trail (~2:05–2:20)
**Screen:** event log, run history, guided tour, reset
**VO:**
> "Every decision is logged — every offer, every rejection, every dispatch — and every run is saved so you can go back and compare. Nothing here is a black box."

### Beat 10 — Say what this is, and isn't (~2:20–end)
**Screen:** world reset
**VO:**
> "To be clear about the limits: this models one zone, not full grid physics. The community and its behavior are modeled, not real customers. This doesn't control real devices. What it does is make a program's assumptions, and its consequences, visible before you ever deploy it."
